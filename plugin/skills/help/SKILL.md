Show the user this, as is:

**VBW turns what you want into proven, committed work.** You agree on
requirements; VBW plans them with tests that fail today, you approve the plan,
VBW builds it in parallel and proves every requirement with those tests, you
check what only a person can judge, and you ship.

| Command | What it does |
|---|---|
| `/vbw:vibe [what you want]` | The one command: takes the project to its next step and tells you when it needs you. `--auto` keeps going on its own until a step needs you |
| `/vbw:init` | Set up VBW in this repository and turn on the VBW status line |
| `/vbw:approve` | Approve the plan, its tests and the commands it may run (only you can) |
| `/vbw:status` | Where the project stands |
| `/vbw:map` | Map an existing codebase before planning |
| `/vbw:debug [the problem]` | Investigate a bug from several angles at once |
| `/vbw:todo [idea]` | Keep an idea for later, or list them |
| `/vbw:teach [convention]` | Teach VBW your project's conventions |
| `/vbw:skills` | Suggest community skills for your stack |
| `/vbw:rtk` | Compress command output to save tokens (RTK) |
| `/vbw:compress [file]` | Compress a long instruction file to save tokens |
| `/vbw:config` | Model profile (quality, balanced, budget) and settings |
| `/vbw:doctor` | Check that everything VBW needs is in place |
| `/vbw:report` | Prepare a bug report about VBW (you review it before anything is sent) |
| `/vbw:update`, `/vbw:whats-new`, `/vbw:uninstall` | Update VBW, see what changed, remove it |

Not VBW commands, and better: for a **quick change**, just ask Claude (VBW's
safety guards stay on); for **web research**, use `/deep-research`.
